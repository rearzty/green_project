# Архитектура

Сервис автоматического проектирования озеленения города с учётом отступов от инженерных сетей (хакатон ЛЦТ2026, трек Департамента природопользования и охраны окружающей среды). Полное описание с источниками, инструкцией по запуску и обоснованием под требования ТЗ — [docs/submission_documentation.md](submission_documentation.md); этот файл — компактная карта кода для тех, кто будет в нём работать.

## Контекст

Полный текст ТЗ и геоданные пилотного проекта (20 московских улиц, АО «Мосгеотрест») открылись 15.09.2026. До этого пайплайн разрабатывался на синтетических территориях (`scripts/generate_synthetic_data.py`); после 15.09 — проверен и доработан на всех 20 улицах реального пилотного датасета (`test_input_data/`, в репозитории отсутствует — это материалы организаторов).

ТЗ прямо расставляет приоритеты: «главное — рабочий алгоритм... UX/UI — по остаточному принципу», «достаточно CLI». Основной сдаваемый артефакт — [scripts/plan_dxf.py](../scripts/plan_dxf.py), консольный пайплайн «чертёж на вход → чертёж с планом посадок на выход», без БД и без веб-сервера. Веб-приложение (backend+frontend) — вторичная, но полностью рабочая надстройка для интерактивной правки.

## Монорепо

```
geo_engine/   Чистая геометрия и НПА-логика, ноль импортов FastAPI:
              io/        чтение DXF/DWG/GeoJSON/SHP, очистка геометрии, запись DXF
              config/    planting_norms.yaml (отступы, источники), species.yaml (породы)
              buffers.py, candidates.py, patterns.py, placement.py, compliance.py,
              territory.py, norms.py, species.py, model.py, planner.py
ml_scoring/   Скоринг кандидатов посадки: HeuristicScorer (прозрачная формула) и
              MLScorer (sklearn), общий интерфейс ScoringStrategy. Зависит только
              от geo_engine.model/geo_engine.norms.
backend/      FastAPI-обвязка поверх geo_engine+ml_scoring: HTTP API, in-process
              хранение проектов/планов (без БД), фоновые задачи генерации/экспорта,
              ручная правка плана по id, чат-ассистент «Юна».
frontend/     Next.js + TypeScript + Tailwind + react-leaflet + three.js —
              интерактивная карта, ручная правка, 3D-просмотр, экспорт.
scripts/      plan_dxf.py (основной CLI), generate_synthetic_data.py, train_synthetic.py.
tests/        Зеркалит geo_engine/ml_scoring/backend — единый каталог, не внутри пакетов.
infra/        Dockerfile.backend (компилирует LibreDWG, использует ODA File Converter),
              Dockerfile.frontend, docker-compose.yml.
```

`geo_engine` и `ml_scoring` не знают друг о друге и не знают о FastAPI — `backend/app/services/pipeline_service.py` и `scripts/plan_dxf.py` независимо друг от друга связывают их вместе (оба — тонкие вызывающие слои над одним и тем же `geo_engine.planner.plan_items()`).

## Пайплайн (CLI и backend вызывают один и тот же код)

1. **Разрешение бандла** (`geo_engine/io/dxf_reader.py::resolve_bundle_inputs`) — на входе либо один файл, либо папка проекта; главный чертёж — самый крупный `.dxf`/`.dwg` в корне, остальные `.dxf`/`.dwg` (в т.ч. во вложенных папках xref/съёмки сетей) читаются вместе с ним.
2. **DWG → DXF**, если нужно (`dwg_convert.py`) — ODA File Converter (основной путь, извлекает ACIS-геометрию `REGION`/`3DSOLID`) или LibreDWG 0.14+ (фолбэк).
3. **Чтение и классификация** (`dxf_reader.py` + `layer_rules.py`) — разворачивание блоков (с защитой от взрыва мусорных блоков), точная и приблизительная (по образцу токенов) классификация слоёв на `object_type`/`zone_type`, поддержка `LWPOLYLINE`/`ARC`/`HATCH`/`REGION`.
4. **Очистка геометрии** (`geometry_cleanup.py`) — сшивка пунктирных линий сетей, реконструкция замкнутых контуров зданий/газона/дороги из линий-соседей, ремонт самопересекающихся колец.
5. **Граница участка** (`territory.py::territory_polygon`) — кластеризация по расстоянию с проверкой контекста (сети рядом), дедупликация почти-дублей до вычитания дырок.
6. **Зона отступов** (`buffers.py::build_exclusion_zone`) — по породе, из `planting_norms.yaml`/`species.yaml` (`norms.py::resolve_setback`), с trace-обоснованием каждого значения.
7. **Buildable area** — территория минус твёрдые препятствия (здания/дороги/тротуары/существующая зелень) минус отступы минус отступ от границы участка.
8. **Кандидаты и паттерны** (`candidates.py`, `patterns.py`) — ряд вдоль улицы/тротуара, группы-куртины, россыпь на остатке; для кустарника — живая изгородь с отдельным шагом.
9. **Скоринг** (`ml_scoring/`) — `HeuristicScorer` (взвешенная сумма признаков) или `MLScorer` (sklearn-модель, `ml_scoring/train_synthetic.py`).
10. **Отбор** (`placement.py::greedy_select`) — жадно по score, без пересечения крон/интервалов, с бюджетом плотности по умолчанию (`planner.DEFAULT_DENSITY_PER_HA`).
11. **Проверка и обоснование** (`compliance.py::explain_items`) — фактические отступы до всех типов ограничений, цитата акта и пункта на каждую позицию.
12. **Экспорт** (`dxf_writer.py::write_dxf`) — копия исходного чертежа + новые слои `GREEN_AI$*`, обоснование как XDATA на каждом объекте; плюс `report.json`/`trace.csv`.

Backend добавляет поверх этого же пайплайна: фоновые задачи (генерация/экспорт — `generation_jobs.py`/`export_jobs.py`), ручную правку по id объектов (`edit_service.py`), растровую подложку слоёв для карты (`layer_raster.py`), чат-ассистента (`assistant_service.py`).

## Данные и состояние

**Базы данных нет** — сознательный выбор по ТЗ-приоритетам и модели использования («загрузили → поработали в одной сессии → забыли»). `backend/app/db/models.py` — обычные `@dataclass`; `backend/app/db/session.py` — `dict[str, Project]` в памяти процесса под одним `threading.Lock`. `Plan` хранит не только построчные позиции, но и «рецепт» (слои проекта + нормативы + режим скоринга) — план без ручных правок можно пересчитать байт-в-байт, поэтому старые немодифицированные планы можно схлопывать (`_prune_stale_plans`), не держа сотни тысяч строк вечно.

## Интерпретируемость (ключевое требование ТЗ)

Допустимость позиции — детерминированная и всегда цитируема (`compliance.py`); ранжирование среди допустимых мест — отдельный, необязательный к цитированию скоринг. Обоснование живёт в трёх местах одновременно: `report.json` (координаты, вид, все проверенные отступы, что сработало), `trace.csv` (плоская таблица посадка×ограничение для Excel) и **XDATA прямо на объекте DXF** (эксперт видит причину, не выходя из CAD). Все три проверены на реальном экспорте пилотных данных (десятки тысяч позиций), не только юнит-тестами.

## Локальный запуск

```bash
python -m scripts.plan_dxf --input <чертёж или папка проекта> --output plan.dxf --types tree,shrub --csv
```

или полный веб-стек:

```bash
docker compose -f infra/docker-compose.yml up --build
```

Backend+Swagger — `localhost:8000/docs`, frontend — `localhost:3000`. Без Docker: `pip install -e ".[dev]"`, `pytest`, `python -m uvicorn backend.app.main:app --reload` (БД не нужна). Полная инструкция, включая сборку DWG-конвертера, — `docs/submission_documentation.md`.
