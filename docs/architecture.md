# Архитектура

Сервис автоматического проектирования озеленения города (хакатон, задача «Сервис для автоматического проектирования озеленения города с учётом расположения подземных коммуникаций и городской среды»).

## Контекст и таймлайн

Реальные ТЗ и геоданные (в т.ч. обезличенные подосновы АО «Мосгеотрест») открываются 15.09.2026, разработка идёт до 29.09.2026. До этой даты весь пайплайн спроектирован и проверен на **синтетических территориях** (`scripts/generate_synthetic_data.py`), чтобы после открытия данных команда занималась интеграцией реальных источников и полировкой UX, а не написанием алгоритма с нуля.

## Монорепо

```
backend/      FastAPI: API-контракт, БД (PostgreSQL+PostGIS), оркестрация geo_engine+ml_scoring
geo_engine/   Чистый пакет: импорт геоданных, буферы отступов, кандидаты посадок, greedy-отбор, экспорт DXF
ml_scoring/   Чистый пакет: скоринг кандидатов — эвристика и ML (обучена на синтетических weak-labeled данных)
frontend/     Next.js + TypeScript + Tailwind + react-leaflet
scripts/      Генерация синтетических тестовых территорий
infra/        Docker-compose (db + backend + frontend) для локальной демонстрации
data/         Синтетические и (позже) реальные геоданные
```

`geo_engine` и `ml_scoring` не зависят от FastAPI/БД и не зависят друг от друга напрямую — `backend/app/services/pipeline_service.py` — единственное место, где они связаны вместе (через инъекцию `ScoringStrategy.as_score_fn()` в `geo_engine.placement.greedy_select`). Это позволяет тестировать геометрию и скоринг юнит-тестами без поднятия сервера, и параллельно работать над разными пакетами не блокируя друг друга.

## Пайплайн генерации плана

1. **Импорт** (`geo_engine/io/`): DXF (`ezdxf`) или GeoJSON/SHP (`GeoPandas`) → `Utility`/`Zone` объекты. DWG предварительно конвертируется в DXF через ODA File Converter (`dwg_convert.py`) — `ezdxf` не читает DWG напрямую.
2. **CRS** (`geo_engine/crs.py`): каждый проект работает в своей метрической проекционной CRS (реальная система координат Мосгеотреста пока неизвестна — решится 15.09); к WGS84 геометрия переводится только на границе API для фронтенда.
3. **Буферы отступов** (`geo_engine/buffers.py`): для каждого типа посадки строится и объединяется буфер по нормативам из `geo_engine/config/planting_norms.yaml` (СП 42.13330.2016, ПП №743-ПП, №623-ПП — значения черновые, требуют проверки по полному тексту ТЗ).
4. **Кандидаты** (`geo_engine/candidates.py`): для деревьев/кустарников — сетка точек с шагом по нормативу, для газона — целые полигоны buildable-территории.
5. **Скоринг** (`ml_scoring/`): `HeuristicScorer` — прозрачная взвешенная сумма признаков (запас по отступу, размер, компактность, зонирование, удалённость от существующей зелени), веса — в коде-конфиге, не хардкод. `MLScorer` — sklearn-пайплайн (`LogisticRegression` поверх тех же признаков), обученный в `ml_scoring/train_synthetic.py` на weak-labeled синтетике (см. `docs/decision_log.md`). Обе реализуют общий интерфейс `ScoringStrategy`.
6. **Отбор** (`geo_engine/placement.py`): жадный алгоритм — сортировка по score, последовательный отбор с проверкой непересечения крон/минимальных расстояний между уже выбранными посадками.
7. **Ручная корректировка**: графическая (`PATCH .../items/{id}`) и структурированная текстовая (`POST .../edit-structured`, фиксированный набор операций — без LLM в критическом пути) — `backend/app/services/edit_service.py`. После правок — повторная проверка нормативов (`POST .../validate`), не блокирующая (предупреждение, а не запрет).
8. **Экспорт DXF** (`geo_engine/io/dxf_writer.py`): слои `TREES`/`SHRUBS`/`LAWN`, точечные посадки — окружности с подписью вида, газон — замкнутая полилиния.

## Данные

PostgreSQL + PostGIS, геометрия хранится в `SRID=0` (без принудительной проекции PostGIS) — CRS каждого проекта трекается как текст в `projects.source_crs`, конвертации делает приложение через `pyproj`. Таблицы: `projects` → `layers` (импортированные коммуникации/зоны) и `plans` → `planting_items` (сгенерированные/скорректированные посадки) → `edit_history` (журнал правок).

## Локальный запуск

```bash
docker compose -f infra/docker-compose.yml up --build
```

Поднимает PostGIS + backend (localhost:8000) + frontend (localhost:3000) одной командой — рассчитано на демонстрацию без интернета на защите.

Для разработки без Docker: backend — `pip install -e ".[dev]"`, `python -m uvicorn backend.app.main:app --reload` (нужен локальный Postgres+PostGIS или `GREENPROJECT_DATABASE_URL` на удалённый); тесты — `pytest`; синтетические данные — `python -m scripts.generate_synthetic_data`; обучение ML — `python -m ml_scoring.train_synthetic`.
