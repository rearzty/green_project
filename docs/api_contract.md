# API-контракт backend ↔ frontend

Все геометрические ответы — GeoJSON (RFC 7946), `EPSG:4326` (WGS84), готовые для Leaflet. Базовый URL берётся фронтендом из `NEXT_PUBLIC_API_URL`.

| Метод | Путь | Описание |
|---|---|---|
| `POST` | `/api/projects` | Загрузка территории (`multipart/form-data`: `name`, `file` — DXF/DWG/ZIP/GeoJSON/SHP, опц. `source_crs`) — запускает DWG-конвертацию + разбор бандла как **фоновую задачу** (на реальном многофайловом ZIP — от десятков секунд до нескольких минут) → `202 {job_id}`. `source_crs` можно не указывать для GeoJSON/SHP в градусах (WGS84) — определяется автоматически и перепроецируется в UTM; для DXF/DWG/ZIP и любой другой метрической CRS `source_crs` по-прежнему обязателен |
| `GET` | `/api/projects/upload/{job_id}` | Статус фоновой задачи загрузки → `{status: "pending"\|"done"\|"error", project_id, error}`. Фронт опрашивает это, затем забирает проект обычным `GET .../{project_id}` |
| `GET` | `/api/projects/{project_id}` | Метаданные проекта (без слоёв — см. `/layers` ниже) |
| `GET` | `/api/projects/{project_id}/layers` | Все слои (коммуникации, здания, зонирование, территория) в виде `FeatureCollection` — отдельный, лениво запрашиваемый эндпоинт (только 3D-вид), на реальном масштабе может быть десятки МБ |
| `GET` | `/api/projects/{project_id}/layers-raster` | Границы + список групп легенды для растровой подложки 2D-карты (не векторные фичи) |
| `GET` | `/api/projects/{project_id}/layers-raster/image?group=...` | PNG одной группы легенды на общей пиксельной сетке |
| `POST` | `/api/projects/{project_id}/generate` | Запускает генерацию как **фоновую задачу** (не ждёт её здесь — на реальном масштабе может занять десятки секунд) → `202 {job_id}` |
| `GET` | `/api/projects/{project_id}/generate/{job_id}` | Статус фоновой задачи генерации → `{status: "pending"\|"done"\|"error", plan_id, error}`. Фронт опрашивает это, затем забирает план обычным `GET .../plans/{plan_id}` — создаёт **новый** `Plan` (не перезаписывает предыдущий), помечает его `is_current` |
| `GET` | `/api/projects/{project_id}/plans` | История всех планов проекта (не только текущий) — `[{plan_id, scoring_mode, created_at, is_current, item_count}]`, без геометрии (для списка/переключателя в UI) |
| `GET` | `/api/projects/{project_id}/plans/{plan_id}` | Один конкретный план (полная геометрия) |
| `DELETE` | `/api/projects/{project_id}/plans/{plan_id}` | Удалить план из истории насовсем, без undo. Отклоняет удаление текущего плана (`409`) |
| `PATCH` | `/api/projects/{project_id}/plans/{plan_id}/items/{item_id}` | Точечная графическая правка (перенос/смена типа/вида) → обновлённый `Feature`. `geometry` — в WGS84 (родная CRS Leaflet), сервер сам перепроецирует в `source_crs` проекта |
| `POST` | `/api/projects/{project_id}/plans/{plan_id}/items/delete` | Удалить объекты по id. Тело `{ids}` → `{deleted_items: [Feature], item_count}` — снэпшоты «до удаления» (для отмены через `items/restore`) и свежий счётчик плана. Неизвестный id → 409, ничего не удаляется |
| `POST` | `/api/projects/{project_id}/plans/{plan_id}/items/retype` | Сменить тип. Тело `{changes: [{id, planting_type}]}` (у каждого свой тип — так работает и отмена) → `{previous_items: [Feature], skipped_ids}`: снэпшоты реально изменённых (геометрия не меняется, фронт правит `planting_type` локально); в `skipped_ids` — объекты, чья геометрия не может иметь такой тип (газон-полигон ↔ дерево/куст-точка) |
| `POST` | `/api/projects/{project_id}/plans/{plan_id}/items/move` | Сдвинуть объекты на вектор протяжки. Тело `{ids, from_point: {x, y}, to_point: {x, y}}` (WGS84 lng/lat) → `{items: [Feature]}` — объекты после переноса (фронт применяет их локально вместо перечитывания всего плана). Атомарно: если хоть один объект вышел бы за границу участка — 400, никто не сдвинут |
| `POST` | `/api/projects/{project_id}/plans/{plan_id}/items/restore` | Восстановить удалённые объекты из снэпшотов (`{items: [Feature]}`, тот же id/геометрия/тип/оценка/`is_manual_edit`) → `{item_count}`. Если объект с таким id уже есть — 409 |
| `POST` | `/api/projects/{project_id}/plans/{plan_id}/validate` | Полная перепроверка плана на нормативы → `{violations: [{item_id, message}]}` — только при открытии плана |
| `POST` | `/api/projects/{project_id}/plans/{plan_id}/validate/items` | То же самое, но только для указанных id (`{ids}`) — сеттбек проверяется независимо для каждого объекта, так что правка не может изменить статус нарушения ни у чего, кроме того, что она сама задела; фронт зовёт это после каждой правки вместо полной проверки, объединяя результат по id |
| `POST` | `/api/projects/{project_id}/plans/{plan_id}/export-dxf` | Запускает экспорт в DXF как **фоновую задачу** (на реальном масштабе — до ~3 минут) → `202 {job_id}` |
| `GET` | `/api/projects/{project_id}/plans/{plan_id}/export-dxf/{job_id}` | Статус фоновой задачи экспорта → `{status: "pending"\|"done"\|"error", error}` |
| `GET` | `/api/projects/{project_id}/plans/{plan_id}/export-dxf/{job_id}/download` | Скачать готовый файл (`Content-Disposition: attachment`) — доступен один раз, после отдачи задача и временный файл удаляются |
| `POST` | `/api/projects/{project_id}/plans/{plan_id}/compliance/items` | Обоснование по нормативам для конкретных посадок (`{ids}`) — тот же `geo_engine.compliance.explain_items`, что и CLI, но по подмножеству и синхронно (дёшево — один `STRtree`-проход) |
| `GET` | `/api/projects/{project_id}/plans/{plan_id}/compliance-report.json` | Полный отчёт по плану — тот же формат, что пишет `scripts/plan_dxf.py` рядом с `--output` |
| `GET` | `/api/projects/{project_id}/plans/{plan_id}/compliance-report.csv` | То же плоской таблицей посадка×ограничение |
| `POST` | `/api/projects/{project_id}/assistant/message` | Чат с ассистентом «Юна»: объясняет план, меняет рецепт генерации, выделяет и правит посадки, запускает экспорт — ответ текстом и списком команд, которые фронт выполняет своими же кнопками. Без языковой модели отвечает встроенным разбором команд (`mode: "rules"`), а не `503` — см. раздел «Юна» ниже |
| `GET` | `/api/config/assistant` | Подключена ли языковая модель: `{llm_configured, provider, model}` |
| `GET` | `/api/config/planting-norms` | Текущий справочник нормативов (для легенды и клиентской валидации) |
| `GET` | `/health` | Liveness-проверка |

## Правка карты — по id объектов, не по зоне

Выделение на карте (клик, рамка, Shift-добавление) и все действия над ним (перенос, смена типа, удаление, отмена/повтор) обращаются к конкретным `item_id`, не к геометрической зоне — повторный вызов позже (например, отмена) действует ровно на те же объекты, независимо от того, что успело переместиться в эту область или из неё за это время. Более раннюю зонную реализацию («убрать в радиусе», «переместить в зоне» и т.п., плюс журнал правок `edit_history`) удалили как неиспользуемый код, когда интерфейс полностью перешёл на правку по id.

## Не блокирующая валидация

Ошибки правок (400 — за границей участка / несовместимый тип и геометрия, 409 — объекты не найдены или уже существуют) отдают в `detail` готовый русский текст для показа пользователю.

`validate` не запрещает нарушения нормативов после ручной правки — у проектировщика может быть обоснованная причина отступить от нормы. Ответ — предупреждение (`violations`), а не отказ в сохранении правки.

## Юна — чат-помощник

Схемы — `backend/app/schemas/assistant.py`, типы фронта — `frontend/lib/api.ts`. Бэкенд ничего не хранит между запросами: историю чата держит фронт и присылает с каждым сообщением.

**Запрос** `POST /api/projects/{project_id}/assistant/message`:

| Поле | Что это |
|---|---|
| `message` | Текст пользователя |
| `history` | Предыдущие реплики `[{role: "user"\|"assistant", content}]`; в модель уходят последние 12 |
| `settings` | Текущий рецепт панели `{planting_types, tree_spacing_m?, shrub_spacing_m?, scoring_mode, tree_rows, trees_in_paving}` — новые значения считаются от него |
| `plan_id`, `selected_item_id` | План на экране и одна посадка в карточке — по ним собирается сводка плана и обоснование посадки (`assistant_context.py`); схлопнутый план (`materialized: false` — его «прибрала» генерация из другой вкладки) сначала пересчитывается тем же `ensure_materialized`, что у остальных роутов. Оба необязательны |
| `selection` | Что выделено на карте: `{count, trees, shrubs, lawns}`; `null` — то же, что ничего |
| `violations_count` | Число посадок с нарушениями; `null` — план ещё не проверен |
| `view` | `"2d"` \| `"3d"` |

**Ответ**: `{reply, actions, action, mode, notice}`.

* `actions` — команды по порядку, фронт выполняет их тем же кодом, что кнопки:
  * `{type: "settings", settings: <полный рецепт>}` — перегенерировать план (`POST .../generate`); несколько изменений из одного сообщения сливаются в одну команду;
  * `{type: "edit_selection", operation: "delete"|"to_tree"|"to_shrub"}` — над текущим выделением, через батч-правки по id, с отменой Ctrl+Z;
  * `{type: "select", target: "violations"|"trees"|"shrubs"|"lawn"|"all"|"none", species?}` — выделить группу; `species` — точное название породы из плана (бэкенд сам приводит «липы» к «Липа мелколистная»);
  * `{type: "ui", command: "export_dxf"|"report_json"|"report_csv"|"show_3d"|"show_2d"}`.
* `action` — устаревшее поле: рецепт первой `settings`-команды или `null`.
* `mode` — кто ответил: `"llm"` (языковая модель) или `"rules"` (встроенный разбор, `assistant_rules.py`).
* `notice` — пояснение для пользователя, например «ИИ сейчас недоступен (исчерпан лимит запросов) — ответила в базовом режиме».

**Режимы.** Модель — любой OpenAI-совместимый chat completions с tool calling (по умолчанию Selectel AI Gateway с GLM-5.3 Flash — нужен только ключ; локальная Ollama; Groq; настройка — `infra/.env.example`). Не настроена → сразу `mode: "rules"`, без `notice` и без ошибки. Настроена, но не ответила (лимит, сеть, таймаут, неверный ключ, пустой или непонятный ответ) → тот же разбор, `mode: "rules"` и `notice` с короткой причиной. Встроенный разбор понимает частые просьбы в разных формулировках: «почему так мало деревьев/кустов» (по разбивке площади участка), «почему эта посадка здесь», «сколько деревьев/кустов/газона/пород», «покажи нарушения», «кусты пореже»/«деревья гуще», «интервал деревьев 6 м», «двумя рядами», «разреши деревья в тротуаре», «без газона»/«только деревья», «режим ML»/«эвристика», «пересчитай план», «выдели все деревья/липы», «сними выделение», «удали выделенные», «сделай их кустами», «скачай DXF», «отчёт CSV», «покажи в 3D»; несколько просьб в одном сообщении объединяет. Модель, вызвавшая инструменты не на все просьбы сообщения (встроенный разбор нашёл больше команд), получает результаты своих вызовов и один дополнительный ход — решает по-прежнему она.

**Правила безопасности — в коде, для обоих режимов** (`assistant_rules.guard_commands`):

1. `edit_selection` без выделения (`selection.count` 0 или `null`) отбрасывается — Юна просит сначала выделить объекты.
2. Любая правка выделения — и удаление, и смена типа — в одном ответе с `select` отбрасывается, в том числе когда выделить не удалось (породы нет в плане, нарушений ноль или проверка не готова, неизвестная цель): править можно только то, что пользователь уже видит выделенным, а «выдели дубы и удали их» без дубов иначе удалило бы текущее выделение. Массовая правка — всегда в два шага: «Выделила … — скажите «удали выделенные» / «сделай их кустами», если…»; при неудачном выделении — «… Удалять ничего не стала». «Сними выделение и удали» не выполняет ни того, ни другого: выделение остаётся, Юна спрашивает, что из двух.
3. Правка выполняется только по прямой просьбе (`assistant_rules.edit_gate`, оба режима). Её нет, если в сообщении есть вопрос или условие — в любом предложении и без «?» («можно удалить выделенные», «удалить ли», «что будет, если сделать их кустами», «удали выделенные. А сколько кустов?»): Юна говорит, что произойдёт, и какой просьбой это сделать. Её нет и при любом отрицании («не», «ни», «нельзя», «подожди» — в том числе с опечатками: «ни удоляй»), исключении («кроме», «остальные», «невыделенные») и просьбе про часть выделенного («удали выделенные кусты», когда выделены и деревья, — Юна просит выделить только нужное).
4. В модельном режиме правку должны прочитать в сообщении и модель, и встроенный разбор; если модель отказалась править, разбор правку вместо неё не выполняет.
5. Выделение, которому заведомо нечего выделить (нарушений 0 или проверка не готова, такого типа в плане нет, плана нет), не отправляется: ответ собирается из фактов, а не из «Выделила посадки с нарушениями» модели.
6. Ослабить нормы отступов нельзя ничем: ни у одной команды нет такого параметра, интервалы зажаты в границы `GenerateRequest` (деревья 0,5–15 м, кусты 0,3–10 м), а `/generate` проверяет их ещё раз.

Если команда отброшена, текст модели заменяется описанием того, что реально сделано, — иначе в ответе осталось бы «удаляю», которого не будет.

**Интервалы в `settings`.** `tree_spacing_m` — нижний предел поверх нормы класса кроны, а не интервал всех деревьев (`geo_engine.planner.norms_for_species`; МГСН 1.02-02 п. 4.2.9.2: широкая крона 8 м, средняя 5 м, узкая 3 м): каждое дерево встаёт не ближе большего из двух, гуще нормы класса деревья не поставить. `null` — по норме; предел не больше 3 м не раздвигает ни одно дерево, поэтому оба режима отдают его как `null`. «Погуще» без заданного предела рецепт не меняет — Юна объясняет это и предлагает то, что может добавить деревья и ещё не включено (двухрядная аллея, деревья в покрытии тротуара); с заданным — ×0,7, а дойдя до нормы — `null`. «Пореже» — ×1,4 от заданного, без него — 7 м (от нормы средней кроны); в ответе — «не меньше 7 м (широким кронам норма — 8 м)». `shrub_spacing_m` заменяет шаг живой изгороди, которой посажена большая часть кустарника (по умолчанию 0,5 м, `planner.IN_ROW_PITCH_M`; куртины — по плотности породы и от интервала не зависят): «погуще» ×0,7, но не меньше 0,3 м (нижняя граница 743-ПП табл. 3.6.2 для низкой изгороди), «пореже» ×1,4. Если модель сдвинула интервал не в ту сторону, о которой просили (например, считала от прежних 5/3 м), действует число встроенного разбора.

**«Удали (все) кусты», «удали липы»** — правка карты в оба режима: выделить группу и попросить подтвердить. Модель, ответившая на такую просьбу иначе (убрала тип из рецепта, удалила текущее выделение, выделила, не спросив), уступает встроенному разбору: его выделение и вопрос. «Убери кусты», «без кустов», «убери/удали кусты из плана», «только деревья» — типы посадок (`settings`).

**Статус** `GET /api/config/assistant` → `{llm_configured: bool, provider: "selectel"|"groq"|"ollama"|"openai-compatible"|"none", model: str|null}`. Ключ не отдаётся никогда.
