# GreenProject

Сервис автоматического проектирования озеленения города с учётом расположения подземных коммуникаций и городской среды. Хакатон ЛЦТ2026, задача Департамента природопользования и охраны окружающей среды г. Москвы.

## Задача в двух словах

По чертежу территории (сети, здания, зонирование, граница участка) сервис сам предлагает, где можно посадить деревья/кустарники/газон, соблюдая нормативные отступы (СП 42.13330.2016, ПП Москвы №743-ПП, МГСН 1.02-02 и др.), даёт скорректировать план вручную и экспортирует итог обратно в чертёж — с обоснованием каждой позиции со ссылкой на конкретный пункт норматива.

**ТЗ прямо расставляет приоритеты:** «главное — рабочий алгоритм... UX/UI — по остаточному принципу... достаточно CLI». Основной сдаваемый артефакт — консольный пайплайн [scripts/plan_dxf.py](scripts/plan_dxf.py) (чертёж на вход → чертёж с планом на отдельном слое на выход, без БД и без веб-сервера). Веб-приложение (backend + карта) — полностью рабочая, но вторичная надстройка для интерактивной правки.

## Статус на сейчас

Пайплайн проверен и доработан на реальных данных пилотного проекта (20 московских улиц, DWG/DXF с внешними ссылками на сети и границу участка) — не только на синтетике. `pytest`: **457 passed, 11 skipped** (skip — тесты на самом пилотном датасете, не входящем в репозиторий; включаются `GREENPROJECT_PILOT_DATA=<путь>`). Реальный экспорт проверен на десятках тысяч позиций (не только на юнит-тестах из нескольких объектов) — геометрия, отступы и XDATA-обоснование совпадают на всём объёме.

Работает end-to-end: загрузка территории (DXF/DWG-бандл или GeoJSON/SHP) → генерация плана (эвристика или ML-скоринг) → ручная правка на карте (выделение, перенос, смена типа, удаление — с undo/redo) → проверка нормативов → экспорт в DXF с обоснованием на каждом объекте плюс JSON/CSV отчёт.

**Известные ограничения** (подробно — раздел 11 в `docs/submission_documentation.md`): система координат реальных данных не подтверждена организаторами; DWG без ODA File Converter (только LibreDWG-фолбэк) теряет геометрию заливок типа покрытия (но не ключевое свойство «не сажать на асфальт» — оно держится на бортовом камне); отступ от ЛЭП сверен частично; двухрядная посадка и целенаправленная расстановка акцентов не реализованы.

## Быстрый старт (Docker, рекомендуется)

```bash
docker compose -f infra/docker-compose.yml up --build
```

- Backend + Swagger: http://localhost:8000/docs
- Frontend: http://localhost:3000

БД не поднимается — она не нужна (состояние проекта живёт в памяти процесса backend, см. `docs/decision_log.md`).

## Основной артефакт по ТЗ — CLI, DXF → DXF

```bash
# один чертёж
python -m scripts.plan_dxf --input site.dxf --output plan.dxf

# папка проекта (реальные данные так и устроены: главный чертёж + сети/граница
# участка отдельными файлами во внешних ссылках)
python -m scripts.plan_dxf \
    --input "<папка улицы>/Генеральный план" \
    --output out/plan.dxf --types tree,shrub --csv
```

На выходе:

| файл | что это |
|---|---|
| `plan.dxf` | копия исходного чертежа + слои `GREEN_AI$ДЕРЕВЬЯ`/`$КУСТАРНИКИ`/`$ГАЗОН`. Исходные слои не тронуты; у каждого объекта плана обоснование в XDATA |
| `plan.report.json` | по каждой посадке: координаты, вид, все проверенные отступы, какой из них определяющий, ссылка на акт и пункт |
| `plan.trace.csv` | то же плоской таблицей — строка на пару «посадка × ограничение», для сверки в Excel |

Код возврата `1`, если хоть один норматив нарушен, `0` иначе — годится для CI.

DWG на входе поддерживается, если на PATH есть конвертер (ODA File Converter — основной путь, LibreDWG **0.14+** — фолбэк) — см. `geo_engine/io/dwg_convert.py`.

Ключи: `--types tree,shrub,lawn`, `--scoring heuristic|ml`, `--pattern auto|row|scatter`, `--tree-spacing`, `--shrub-spacing`, `--density tree=25,shrub=250`, `--prefix` (префикс слоёв результата), `--plan-key` (одинаковый ключ даёт побитово тот же план).

## Локальная разработка без Docker

### Backend

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows
pip install -e ".[dev]"

python -m scripts.generate_synthetic_data   # тестовые территории в data/synthetic/ (опционально)
python -m ml_scoring.train_synthetic        # обучить ML-скоринг (нужно для scoring_mode=ml)
pytest                                       # прогнать тесты

python -m uvicorn backend.app.main:app --reload   # БД поднимать не нужно
```

Python зафиксирован на 3.11 (`.python-version`) — на более новых версиях риск проблем со сборкой геозависимостей (GDAL/Fiona/Shapely/pyproj).

### Frontend

```bash
cd frontend
npm install
cp .env.local.example .env.local
npm run dev
```
