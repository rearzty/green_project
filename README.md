# GreenProject

Сервис автоматического проектирования озеленения города с учётом расположения подземных коммуникаций и городской среды. Хакатон ЛЦТ2026, задача Департамента природопользования и охраны окружающей среды г. Москвы.

## Задача в двух словах

По чертежу территории (сети, здания, зонирование, граница участка) сервис сам предлагает, где можно посадить деревья/кустарники/газон, соблюдая нормативные отступы (СП 42.13330.2016, ПП Москвы №743-ПП, МГСН 1.02-02 и др.), даёт скорректировать план вручную и экспортирует итог обратно в чертёж — с обоснованием каждой позиции со ссылкой на конкретный пункт норматива.

**ТЗ прямо расставляет приоритеты:** «главное — рабочий алгоритм... UX/UI — по остаточному принципу... достаточно CLI». Основной сдаваемый артефакт — консольный пайплайн [scripts/plan_dxf.py](scripts/plan_dxf.py) (чертёж на вход → чертёж с планом на отдельном слое на выход, без БД и без веб-сервера). Веб-приложение (backend + карта) — полностью рабочая, но вторичная надстройка для интерактивной правки.

## Статус на сейчас

Пайплайн проверен и доработан на реальных данных пилотного проекта (20 московских улиц, DWG/DXF с внешними ссылками на сети и границу участка) — не только на синтетике. **Сквозной прогон всех улиц пилота: считаются 18 из 19 улиц с чертежами, нарушений нормативов 0** (не считается «7. Нижние Поля» — во входных данных нет границы работ; у «11. Фрунзенская» чертежей нет вовсе). `pytest`: **504 passed, 11 skipped** (skip — тесты на самом пилотном датасете, не входящем в репозиторий; включаются `GREENPROJECT_PILOT_DATA=<путь>`). Реальный экспорт проверен на десятках тысяч позиций (не только на юнит-тестах из нескольких объектов) — геометрия, отступы и XDATA-обоснование совпадают на всём объёме.

Работает end-to-end: загрузка территории (DXF/DWG-бандл или GeoJSON/SHP) → генерация плана (эвристика или ML-скоринг) → ручная правка на карте (выделение, перенос, смена типа, удаление — с undo/redo) → проверка нормативов → экспорт архивом: план поверх исходного главного чертежа с обоснованием на каждом объекте, файлы внешних ссылок рядом (AutoCAD открывает весь проект), JSON/CSV отчёт.

После генерации для каждого типа посадки показано, сколько площади участка оставили нормы и что заняло остальное — на плотных улицах табличные отступы от края проезжей части и кабелей почти не оставляют места деревьям, и это видно сразу, а не выглядит сбоем.

**Известные ограничения** (подробно — раздел 11 в `docs/submission_documentation.md`): система координат реальных данных не подтверждена организаторами; на плотных улицах табличные отступы оставляют деревьям единицы процентов площади (проектировщики сажают ближе — с защитными мерами, которые таблица не учитывает); отступ от ЛЭП сверен частично; целенаправленная расстановка акцентов не реализована.

## Оценка качества на решениях проектировщиков

План сравнивается с настоящими посадочными чертежами проектировщиков пилота
(10 улиц, 2479 деревьев): какая доля их мест найдена, какая доля наших деревьев
стоит там же, F1. Методика, числа и найденная по ним ошибка чтения бортового
камня — **[docs/evaluation.md](docs/evaluation.md)**. Там же модель «где бы
посадил проектировщик» (режим «ML»): F1 0,126 → 0,155 на улицах, которых она
не видела при обучении.

```bash
export GREENPROJECT_PILOT_DATA="<…>/Пилотный проект 20 улиц"
python -m scripts.evaluate --only-reference --scoring heuristic --jobs 4
```

## Быстрый старт (Docker, рекомендуется)

```bash
docker compose -f infra/docker-compose.yml up --build
```

- Backend + Swagger: http://localhost:8000/docs
- Frontend: http://localhost:3000

Сборка ставит ODA File Converter (основной конвертер DWG) и пишет в лог, удалось ли: строка `ODA File Converter: установлен` — всё в порядке, `!!! ... НЕ установлен` — DWG пойдёт через запасной LibreDWG с худшим качеством.

**Из России сайт ODA недоступен** (403, страна под санкциями OFAC), и сборка молча получит LibreDWG — даже на x86-64. Положите установщик `ODAFileConverter_QT6_lnxX64_*.deb` в `infra/vendor/` (см. [infra/vendor/README.md](infra/vendor/README.md)) — образ возьмёт его оттуда. Какой конвертер сработал, видно и в веб-панели: при LibreDWG после загрузки появляется предупреждение.

БД не поднимается — она не нужна (состояние проекта живёт в памяти процесса backend, см. `docs/decision_log.md`).

## Основной артефакт по ТЗ — CLI, DXF → DXF

```bash
# один чертёж
python -m scripts.plan_dxf --input site.dxf --output plan.dxf

# папка проекта (реальные данные так и устроены: главный чертёж + сети/граница
# участка отдельными файлами во внешних ссылках)
python -m scripts.plan_dxf \
    --input "<папка улицы>/Генеральный план" \
    --output out/plan.dxf --types tree,shrub --csv
```

На выходе:

| файл | что это |
|---|---|
| файлы внешних ссылок | исходные листы проекта, на которые ссылается главный чертёж, — по тем же относительным путям, AutoCAD подгрузит их сам |
| `plan.dxf` | копия исходного главного чертежа + слои `GREEN_AI$ДЕРЕВЬЯ`/`$КУСТАРНИКИ`/`$ГАЗОН`. Исходные слои не тронуты; у каждого объекта плана обоснование в XDATA |
| `plan.report.json` | по каждой посадке: координаты, вид, все проверенные отступы, какой из них определяющий, ссылка на акт и пункт |
| `plan.trace.csv` | то же плоской таблицей — строка на пару «посадка × ограничение», для сверки в Excel |

Код возврата `1`, если хоть один норматив нарушен, `0` иначе — годится для CI.

DWG на входе поддерживается, если на PATH есть конвертер (ODA File Converter — основной путь, LibreDWG **0.14+** — фолбэк) — см. `geo_engine/io/dwg_convert.py`.

Ключи: `--types tree,shrub,lawn`, `--scoring heuristic|ml`, `--pattern auto|row|scatter`, `--tree-spacing`, `--shrub-spacing`, `--density tree=25,shrub=250`, `--tree-rows 2` (двухрядная аллея деревьев вдоль улиц по 743-ПП табл. 3.6.2, по умолчанию однорядная), `--prefix` (префикс слоёв результата), `--plan-key` (одинаковый ключ даёт побитово тот же план).

В консоли печатается время каждого этапа (чтение, граница, генерация, проверка, запись) и общее время прогона.

## Локальная разработка без Docker

### Backend

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows
pip install -e ".[dev]"

python -m scripts.generate_synthetic_data   # тестовые территории в data/synthetic/ (опционально)
python -m ml_scoring.train_synthetic        # обучить ML-скоринг (нужно для scoring_mode=ml)
pytest                                       # прогнать тесты

python -m uvicorn backend.app.main:app --reload   # БД поднимать не нужно
```

Python зафиксирован на 3.11 (`.python-version`) — на более новых версиях риск проблем со сборкой геозависимостей (GDAL/Fiona/Shapely/pyproj).

### Frontend

```bash
cd frontend
npm install
cp .env.local.example .env.local
npm run dev
```
