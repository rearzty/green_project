# GreenProject

Сервис автоматического проектирования озеленения города с учётом расположения подземных коммуникаций и городской среды. Делается для международного хакатона 2026 (трек «Социальные задачи»).

## Задача в двух словах

Организаторы просят ИИ-агента, который по геоподоснове территории (коммуникации, здания, зонирование) сам предлагает, где можно посадить деревья/кустарники/газон, соблюдая нормативные отступы от инженерных сетей (СП 42.13330.2016, ПП Москвы №743-ПП, №623-ПП), даёт скорректировать план вручную и экспортирует итог обратно в DXF.

**Важный момент по таймингу:** реальные данные и полное ТЗ от организаторов (в т.ч. геоподосновы «Мосгеотреста») открываются только **15.09.2026**, разработка идёт до 29.09.2026. Всё, что есть в репозитории сейчас, сделано и проверено **на синтетических тестовых территориях** — чтобы с 15.09 команда занималась подключением реальных данных и доводкой UX, а не написанием алгоритма с нуля.

## Команда

- **Бэкенд/деплой/инфра** — Тихон
- **ML/данные** — соразработчица
- **Фронтенд** — собран с помощью Claude (Next.js + Tailwind + react-leaflet), дальше дорабатывается по необходимости любым из участников

## Как оно устроено — коротко

Детерминированная геометрия (буферы нормативных отступов → допустимые зоны → кандидаты посадок → жадный отбор) + отдельный слой скоринга кандидатов (прозрачная эвристика **и** ML-модель, обученная на синтетических weak-labeled данных — честно, без реальной разметки её пока просто не существует). Backend на FastAPI + PostgreSQL/PostGIS, фронт — карта на Leaflet, экспорт плана в DXF.

## Статус на сейчас

Работает end-to-end на синтетических территориях (`data/synthetic/`, генерируются скриптом): загрузка территории → генерация плана (эвристика или ML) → проверка нормативов → экспорт в DXF. Проверено не только тестами, но и вручную через докер и браузер. 11/11 pytest зелёные.

**Чего не хватает и что дальше** (не блокирует текущую основу, но нужно после 15.09):
- Подключить реальные геоданные Мосгеотреста вместо синтетики — CRS территорий пока неизвестна, `geo_engine` спроектирован так, чтобы принять любую метрическую CRS без хардкода.
- Обратная репроекция геометрии при графической правке (drag на карте сейчас в WGS84, а хранится всё в CRS проекта) — см. TODO в `backend/app/services/edit_service.py`.
- Проверка/установка ODA File Converter для DWG→DXF (если организаторы дадут DWG, а не DXF).
- Ревизия точных значений нормативных отступов в `geo_engine/config/planting_norms.yaml` по полному тексту ТЗ (сейчас — черновые значения из описания задачи).

## Быстрый старт (Docker, рекомендуется)

```bash
docker compose -f infra/docker-compose.yml up --build
```

- Backend + Swagger: http://localhost:8000/docs
- Frontend: http://localhost:3000

Проверить на синтетике: загрузи через интерфейс любой файл из `data/synthetic/territory_*.geojson` (сгенерировать новые — `python -m scripts.generate_synthetic_data`), нажми «Сгенерировать план». Карта после загрузки покажет территорию где-то на карте мира сильно увеличенной/уменьшенной — это ожидаемо, у синтетики нет реальной геопривязки (метры читаются как градусы), не баг.

## Локальная разработка без Docker

### Backend

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows
pip install -e ".[dev]"

python -m scripts.generate_synthetic_data   # тестовые территории в data/synthetic/
python -m ml_scoring.train_synthetic        # обучить ML-скоринг на синтетике
pytest                                      # прогнать тесты

# нужен запущенный PostgreSQL+PostGIS (или GREENPROJECT_DATABASE_URL на внешний)
python -m uvicorn backend.app.main:app --reload
```

Python зафиксирован на 3.11 (`.python-version`) — на более новых версиях есть риск проблем со сборкой geo-зависимостей (GDAL/Fiona/Shapely/pyproj).

### Frontend

```bash
cd frontend
npm install
cp .env.local.example .env.local
npm run dev
```
